## 二、网络层架构（3 层服务器模型）

服务端同时运行三个独立的 MINA `NioSocketAcceptor` 实例：

```
┌──────────────────────────────────────────────────────────────────┐
│                        MapleServerHandler                        │
│                  (单例，处理所有网络事件)                            │
└──────────────────────────────────────────────────────────────────┘
          ▲                     ▲                     ▲
          │                     │                     │
┌─────────┴──────────┐ ┌───────┴──────────┐ ┌───────┴──────────┐
│  AuthenticationServer│ │  ChannelServer   │ │  CashShopServer  │
│  (登录服务器)        │ │  (频道服务器)     │ │  (商城服务器)     │
│  端口: server.login  │ │  端口: 7575+(多   │ │  端口: 8600      │
│  .port = 9595       │ │  频道)           │ │                  │
└────────────────────┘ └──────────────────┘ └──────────────────┘
```

### 2.1 连接生命周期

```
客户端连接
    │
    ▼
sessionOpened()          ← 端口判定是登录/频道/商城 + 防洪水检测
    │
    ▼
生成 MapleAESOFB 加解密实例    ← 使用 MAPLE_VERSION 和随机 IV
    │
    ▼
发送 HELLO 握手包          ← 包含版本号和 IV
    │
    ▼
messageReceived()          ← 通过 RecvPacketOpcode 枚举分发
    │
    ▼
handlePacket(opcode, data, client, cs)
    │
    ▼
对应的 Handler.xxx() 静态方法
```

### 2.2 协议编解码

- **MapleCodecFactory** — MINA `ProtocolCodecFactory`
  - **MaplePacketEncoder** — 使用 `MapleAESOFB` 加密，AES OFB 模式 + 自定义抹字表
  - **MaplePacketDecoder** — 使用 `MapleAESOFB` 解密，保存解码状态（`DecoderState`）
- 封包格式：`[长度(2字节)][opcode(2字节)][加密负载]`
- Opcode 映射：`recvops.properties` (客户端→服务端)、`sendops.properties` (服务端→客户端)
- 加密封装类：`MapleAESOFB` — AES OFB 模式，32 字节密钥 + 自定义 256 字节抹字表

### 2.3 服务器详情

| 服务器 | 类 | 端口 | 职责 |
|---|---|---|---|
| 登录 | `AuthenticationServer` | 9595 | 账号认证、角色列表、角色创建/删除 |
| 频道 | `ChannelServer` | 7575+(多频道) | 游戏主逻辑：地图、怪物、NPC、交互 |
| 商城 | `CashShopServer` | 8600 | 商城购买、MTS 拍卖 |

### 2.4 跨频道通信

`World` 类（`handling/world/World.java`）是全局状态的枢纽，通过静态内部类管理跨频道共享数据：

- `World.Find` — 查找角色所在的频道
- `World.Party` — 组队管理（跨频道同步队伍状态）
- `World.Guild` — 公会管理
- `World.Family` — 家族管理
- `World.Alliance` — 联盟管理
- `World.Messenger` — 跨频道聊天
- `World.Broadcast` — 全局广播

## 三、数据包分发系统

中心分发器位于 **`MapleServerHandler.handlePacket()`**（约 600 行 switch-case）：

```
接收数据包
    │
    ▼
读取 header_num → 遍历 RecvPacketOpcode 枚举匹配
    │
    ▼
状态检查 (checkState): 未登录状态只允许登录相关 opcode
    │
    ▼
switch(opcode):
    ├── LOGIN_PASSWORD        → CharLoginHandler.login()
    ├── SERVERLIST_REQUEST    → CharLoginHandler.ServerListRequest()
    ├── CHARLIST_REQUEST      → CharLoginHandler.CharlistRequest()
    ├── CREATE_CHAR           → CharLoginHandler.CreateChar()
    ├── MOVE_PLAYER           → PlayerHandler.MovePlayer()
    ├── CLOSE_RANGE_ATTACK    → PlayerHandler.closeRangeAttack()
    ├── USE_ITEM              → InventoryHandler.UseItem()
    ├── GENERAL_CHAT          → ChatHandler.GeneralChat()
    ├── NPC_TALK              → NPCHandler.NPCTalk()
    ├── CHANGE_MAP            → PlayerHandler.ChangeMap() 或 CashShopOperation.LeaveCS()
    ├── ENTER_CASH_SHOP       → InterServerHandler.EnterCS()
    ├── ... (80+ opcodes)
    └── (opcode 未匹配)        → 日志记录"未处理"
```

Handler 类列表 (`handling/channel/handler/`)：

| Handler | 职责 |
|---|---|
| `PlayerHandler` | 移动、攻击、技能、换图、椅子、表情 |
| `InventoryHandler` | 道具使用/移动/排序/拾取/强化/制造 |
| `NPCHandler` | NPC 对话、商店 |
| `MobHandler` | 怪物移动/伤害 |
| `PetHandler` | 宠物相关 |
| `SummonHandler` | 召唤兽控制 |
| `PartyHandler` | 组队操作 |
| `GuildHandler` | 公会管理 |
| `FamilyHandler` | 家族管理 |
| `BuddyListHandler` | 好友列表 |
| `ChatHandler` | 聊天 |
| `PlayersHandler` | 人气、纸条、传送门 |
| `InterServerHandler` | 换频道、进入商城 |
| `UserInterfaceHandler` | UI 交互 |

## 四、游戏数据模型

### 4.1 领域模型 (EBean ORM)

所有实体类以 `D` 开头（Legacy 命名），位于 `com.github.mrzhqiang.maplestory.domain`，继承 `io.ebean.Model`。

**核心实体关系：**

```
DAccount (1) ──── (N) DCharacter
    │                    │
    │                    ├── DSavedLocation (保存位置)
    │                    ├── DKeyMap (按键映射)
    │                    ├── DSkill (技能)
    │                    ├── DSkillCooldown (技能冷却)
    │                    ├── DQuestStatus (任务状态)
    │                    ├── DRegrockLocation / DTrockLocation (传送记录)
    │                    ├── DWishList (愿望单)
    │                    ├── DMountData (坐骑)
    │                    ├── DSkillMacro (宏)
    │                    ├── DBuddy (好友)
    │                    └── (通过 accountId 关联)
    │
    ├── DGuild (公会)
    ├── DFamily (家族)
    └── DCsEquipment / DCsItem (商城储物箱)

DInventorySlot (背包格子) ─── DInventoryEquipment / DInventoryItem
DMtsCart / DMtsItem / DMtsEquipment (拍卖行)
DDropData / DDropDataGlobal (掉落数据)
DWzItemData / DWzItemEquipData / DWzItemAddData (WZ 道具数据)
```

**每个实体**通过 EBean 的 `@WhenCreated` / `@WhenModified` 自动管理时间戳。查询 Bean（`QDAccount`, `QDCharacter` 等）通过 Maven 编译期注解自动生成。

### 4.2 客户端模型 (`client/`)

| 类 | 职责 |
|---|---|
| `MapleClient` | 网络会话封装，持有 IoSession、AES 加密器、账号/角色状态 |
| `MapleCharacter` | 玩家实体——属性、背包、技能、任务、宠物、工会、组队等（约 2000+ 行） |
| `MapleStat` | 角色属性枚举 (HP/MP/STR/DEX/INT/LUK 等) |

| `SkillFactory` | 技能数据工厂 |
| `LoginCrypto` | 密码加密 (SHA-1 + 盐) |

- 基础属性（等级、职业、经验、声望、AP/SP）
- 背包（6 种类型：装备/消耗/设置/其他/特殊/现金）
- 技能与冷却
- 任务进度
- 好友列表/组队/公会
- 宠物/坐骑/戒指
- 抗作弊跟踪器 (`CheatTracker`)
- 宏/快捷键

## 六、脚本系统

使用 Nashorn JavaScript 引擎，脚本位于 `脚本/` 目录。

| 管理器 | 触发时机 | 脚本目录 |
|---|---|---|
| `NPCScriptManager` | 玩家与 NPC 对话 | `脚本/npc/*.js` |
| `PortalScriptManager` | 玩家穿过传送门 | `脚本/传送点/*.js` |
| `EventScriptManager` | 游戏事件触发 | `脚本/事件/*.js` |
| `ReactorScriptManager` | 玩家攻击反应堆 | `脚本/反应堆/*.js` |

NPC 对话流程：

```
MapleCharacter → NPC 对话请求
    │
    ▼
NPCHandler.NPCTalk() → NPCScriptManager.start(client, npcId)
    │
    ▼
AbstractScriptManager.getInvocable("npc/<npcId>.js", ...)
    │
    ▼
Nashorn 执行脚本 → NPCConversationManager API
    │
    ├── cm.sendNext("文本")      → 发送对话
    ├── cm.getItem(id)          → 获取道具
    ├── cm.gainItem(id, count)  → 给予道具
    ├── cm.warp(mapId)          → 传送地图
    └── cm.dispose()            → 结束对话
```

## 七、依赖注入 (Guice)

```
Injectors (枚举单例)
    │
    └── Guice.createInjector(
            ConfigurationModule,    ← 加载 服务端配置.ini → Properties → ServerProperties
            DatabaseModule,         ← DataSourceConfig → EBean Database → Query Beans
            MinaModule              ← NioSocketAcceptor, ProtocolCodecFilter
        )
```

所有服务类使用 `@Inject` 和 `@Singleton`，通过 Guice 自动注入。全局静态访问入口 `Injectors.get(Class)` 用于在非注入上下文中获取实例（如遗留工具类）。

`DatabaseModule` 注册了三个查询 Bean Provider: `QDAccount`, `QDCharacter`, `QDGuild`。

## 十三、WZ (游戏资源) 系统

WZ 文件是 MapleStory 的原始资源包，本服务端使用 XML 格式（通过 wz2xml 转换）。

**WZ 数据类型** (`wz/element/`)：
- `ImgdirElement` — 目录节点
- `CanvasElement` / `VectorElement` / `UolElement` 等 — 各种值节点

加载流程：
```
WzResource.load() → Flowable.fromIterable(WzData.values())
    │                 各 WzData 枚举对应一个 .wz 目录
    ▼
WzDirectory (目录结构) → WzFile (.img.xml 文件) → ImgdirElement (树形数据)
    │
    ▼
WzLoadSubscriber.onNext() → 各模块解析
```

WZ 数据主要用于道具信息、技能数据、地图配置等服务器端逻辑，**不需要完整客户端 WZ 文件**。

## 十四、数据结构与工具

### 核心工具类

| 工具类 | 用途 |
|---|---|
| `MaplePacketCreator` | 构建所有出站数据包（~4000 行） |

## 十五、数据库

### 初始化
- `db/ms079.sql` — 完整建表脚本
- EBean 自动迁移：`src/main/resources/dbmigration/`

### 数据源配置
`DatabaseModule` 从 `服务端配置.ini` 读取 `datasource.*` 属性，创建 EBean `DataSourceConfig` → `Database`。

### 缓存模式
关键数据使用 Guava Cache（如公会 `LoadingCache`、队伍 `Cache`）减少数据库查询。

## 十六、关闭流程

```
ShutdownServer.run() (通过 Runtime ShutdownHook)
    │
    ├── 1. 停止所有 Timer 线程池
    ├── 2. 关闭所有雇佣商店
    ├── 3. 保存公会/联盟/家族
    ├── 4. 广播关闭公告 → 每个频道保存所有玩家
    ├── 5. 关闭所有频道服务器
    ├── 6. 关闭登录服务器
    ├── 7. 关闭商城服务器
    ├── 8. 关闭 EBean 数据库连接池
    └── 9. System.exit(0)
```
