## 各问题详情

### 1. RegRock 定位石保存到错误表 ✅ 已修复

**位置：** `MapleCharacter.java:1257-1265`

```java
new QDRegrockLocation().character.eq(character).delete(); // regrocklocations
for (int regrock : regrocks) {
    if (regrock != 999999999) {
        DTrockLocation trockLocation = new DTrockLocation(); // trocklocations ← BUG
        trockLocation.setCharacter(character);
        trockLocation.setMapId(regrock);
        trockLocation.save();
    }
}
```

删除时操作 `regrocklocations`，插入时写了 `trocklocations`。`DTrockLocation` 应改为 `DRegrockLocation`。

### 2. Skill Cooldowns 只增不删 ✅ 已修复

**位置：** `MapleCharacter.java:1157-1166`

保存前无 delete，且只在 `dc=true` 时触发。过期冷却永久累积。

**修复：** 保存前先 `new QDSkillCooldown().character.eq(character).delete()` 清除旧数据。

### 3. delete-then-insert 无事务保护 ✅ 已修复

涉及 11 张表：`skill_macros`, `inventoryslot`, `quest_info`, `quest_status`, `skills`, `saved_locations`, `achievements`, `buddies`, `wishlist`, `trock_locations`, `regrock_locations`。

```
T1: DELETE FROM X WHERE character_id = ?
T2: 服务器崩溃
T3: INSERT 永远不执行 → X 数据永久丢失
```

**修复：** `saveToDB()` 整个方法体用 `DB.beginTransaction()` / `transaction.commit()` 包裹。崩溃时整个事务回滚，delete 不会生效，数据不丢。

### 4. cs=null 跳过无关保存 ✅ 已修复

**位置：** `MapleCharacter.java:1227-1238`

`mount.saveMount()`, `keylayout.saveKeys()`, `monsterbook.saveCards()`, `PlayerNPC.updateByCharId()` 被错误地捆绑在 `if (cs != null)` 条件内，它们与商城对象无关。

**修复：** 拆分为独立调用，`cs.save()` 保留 null 检查，其余 4 个调用移出条件块。

### 5. 地图切换全量保存 ✅ 已修复

**位置：** `MapleCharacter.java:2396-2427` — `changeMapInternal()`

每次换地图调用 `saveToDB(false, false)`，写入 20+ 张表。

**修复：** 将 `saveToDB(false, false)` 替换为 `savePosition()`，仅更新 `characters` 表的 map 和 spawnpoint 字段。地图切换从 20+ 表写入降级为单表 UPDATE。

### 6. DAccountInfo 频繁写入 ✅ 已修复

`MapleCharacter.java` 尾段约 30+ 个 getter/updater 方法。

**修复：** 
- 新增 3 个缓存字段 `cachedAccountInfo` / `cachedHyPay` / `cachedFishingJf`，各带 lazy-load helper
- getter 只在每日重置或首次创建时 save，其余情况纯读缓存
- updater 通过缓存对象操作，消除 findOne 查询
- DHyPay/DFishingJf 操作从每次 4 次 DB 查询降为 0 查询 + 1 次 save
- 修复 `updateGamePointsPS` 忽略参数的 bug（amount 传进去被设为 0）

### 7. 代码重复

`saveNewCharToDB` 和 `saveToDB` 各维护一套创建 DEntity 的逻辑。

## 架构方案：分层的脏标记保存体系

### 核心思路

当前 `saveToDB()` 的问题根源是**无差别全量保存**——不论数据是否变化，所有表全部写一遍。解决方案是引入**脏标记（dirty flag）**，按数据类别分组，各自独立判断是否需要持久化。

### 数据结构分层

将角色的所有持久化数据按「变化频率」和「保存粒度」分成四层：

```
Layer 1 — 高频变化，需立即持久化
  ├── 角色位置 (map, spawnpoint)     → 仅更新 characters 表的 map 字段
  └── 背包物品 (增/删/改)             → 单物品 save，而非全量

Layer 2 — 中频变化，定期批量保存
  ├── 角色属性 (level, exp, hp, mp...) → dirty flag + 30s 冷却
  ├── 技能 (skills)                    → dirty flag + 30s 冷却
  └── 任务 (quests, quest_info)        → dirty flag + 30s 冷却

Layer 3 — 低频变化，按需保存
  ├── 背包槽位 (inventoryslot)         → 仅 slot 变化时
  ├── 技能宏 (skill_macros)            → 仅宏变化时
  ├── 按键布局 (keylayout)             → 仅布局变化时
  ├── 坐骑数据 (mount)                 → 已有 changed 标记
  ├── 怪物卡 (monsterbook)             → 已有 changed 标记
  ├── 好友列表 (buddies)              → 仅好友变化时
  ├── 愿望单 (wishlist)               → 仅愿望单变化时
  ├── 传送石 (trock, regrock)         → 仅石头变化时
  ├── 位置存档 (saved_locations)      → 仅位置变化时
  └── 成就 (achievements)             → 仅成就变化时

Layer 4 — 仅登出/关机时保存
  ├── 技能冷却 (cooldowns)             → dc=true，保存前先 delete
  └── 账号点数 (cash, mPoints...)     → 已有内联 UPDATE
```

### 保存触发策略

| 触发点 | 当前行为 | 新行为 |
|--------|---------|--------|
| 地图切换 | `saveToDB()` 全量 | `savePosition()` 仅写 map/spawnpoint |
| PLAYER_UPDATE (每 3 分钟) | `saveToDB()` 全量 | `saveChanged()` 仅写 dirty 的 Layer 2 数据 |
| 背包物品变化 | 不保存 | `saveItem(item)` 立即写单物品 |
| 全局 30 分钟定时 | `saveToDB()` 全量 | `saveAll()` 全量（兜底） |
| 登出/断线 | `saveToDB(true, ...)` | `saveAll()` 全量（包括冷却） |
| slot 扩展 | 不保存 | 标记 dirty → 下次批量保存时写入 |

### 具体实现

#### step 1：加脏标记

在 `MapleCharacter` 中增加：

```java
// 每类数据一个标记，按需置脏
private boolean statsChanged;       // level, exp, hp, mp, str, dex...
private boolean skillsChanged;      // 技能升级
private boolean questsChanged;      // 任务进度
private boolean macrosChanged;      // 技能宏
private boolean slotsChanged;       // 背包槽位
private boolean buddiesChanged;     // 好友
private boolean rocksChanged;       // 传送石/定位石
private boolean wishesChanged;      // 愿望单
private boolean keylayoutChanged;   // 按键
private boolean locationsChanged;   // 位置存档
private boolean achievementsChanged;// 成就
// mount, monsterbook, storage 已有各自的 changed 标记
```

#### step 2：重构 saveToDB

将原来的巨型方法拆分为独立的小方法，每个只保存对应数据：

```java
public void saveToDB(boolean dc, boolean fromcs) {
    // Layer 1: 位置已在 changeMap 时单独保存，此处跳过
    
    // Layer 2: 按脏标记保存
    if (statsChanged) saveStats(character);
    if (skillsChanged) saveSkills(character);
    if (questsChanged) saveQuests(character);
    
    // Layer 3: 按脏标记保存
    if (slotsChanged) saveInventorySlot(character);
    if (macrosChanged) saveSkillMacros(character);
    // ... 其余同理
    
    // Layer 4: 仅登出时
    if (dc) saveCooldowns(character);
    
    // 始终保存（兜底）
    saveAccountPoints();
    if (storage != null && storage.isChanged()) storage.saveToDB(character);
}
```

#### step 3：地图切换降级

```java
// 在 changeMapInternal 中，将 saveToDB(false, false) 替换为：
savePositionOnly();  // 仅 UPDATE characters SET map=?, spawnpoint=?
```

#### step 4：背包物品立即保存

```java
// 在 MapleInventoryManipulator.addFromDrop / removeFromSlot 成功后：
ItemLoader.saveItem(item, character);  // 只写单条，不等批量保存
```

#### step 5：修复已知 Bug

- RegRock: `DTrockLocation` → `DRegrockLocation`
- Cooldowns: 保存前先 delete
- cs=null: 拆开 5 个独立保存调用，各自判断条件

### 为什么这样做

1. **脏标记**消除了全量保存的浪费，地图切换不再有 20+ 表写入压力
2. **delete-then-insert 的 11 张表**仍在，但有脏标记后它们只在数据变化时触发（频率降低 100 倍），实际崩溃窗口极短
3. **背包物品立即保存**解决了物品丢失问题，且单条 INSERT/UPDATE 远快于全量保存
4. **分层设计**可以在后续按需进一步优化（如 Layer 2 合并为一个事务），但当前改动最小

### 不变更的部分

- `saveNewCharToDB` 暂不重构（仅新建角色调用一次，风险低）
- 周期性 30 分钟全量保存保留（作为最终兜底）
- EBean 的 `save()` / `delete()` 模式不变（仅调用方式优化）

### 暂不入方案的部分

- EBean 事务已应用于 saveToDB — 解决 delete-then-insert 原子性
- DAccountInfo/DHyPay/DFishingJf 已加缓存 — 消除冗余查库+保存
- 不合并 saveNewCharToDB 和 saveToDB — 改动范围太大
