# MapleStory v079 数据库表结构与模型文档

## 1. 概述

### 1.1 技术栈

| 组件 | 版本/技术 |
|---|---|
| 数据库 | MySQL 8.0（InnoDB + MyISAM 混用） |
| ORM | EBean (io.ebean) |
| 依赖注入 | Google Guice 5 |
| 数据库名 | `ms079` |
| 字符集 | utf8_general_ci / gbk_chinese_ci / latin1_swedish_ci |

### 1.2 配置加载方式

数据库连接配置不在源码内的 `application.properties` 中，而是从**外部配置文件** `服务端配置.ini` 运行时加载：

```
ConfigurationModule → Properties → DatabaseModule → DataSourceConfig → EBean Database
```

DI 模块路径：
- `src/main/java/com/github/mrzhqiang/maplestory/di/ConfigurationModule.java` — 加载外部 .ini 配置
- `src/main/java/com/github/mrzhqiang/maplestory/di/DatabaseModule.java` — 提供 `Database` 和 `QDAccount` / `QDCharacter` / `QDGuild` 查询 Bean
- `src/main/java/com/github/mrzhqiang/maplestory/di/Injectors.java` — Guice 注入器入口

### 1.3 Schema 文件

| 文件 | 说明 |
|---|---|
| `db/ms079.sql`（~128000+ 行） | Navicat 导出的原始建库脚本，含大量初始数据（商城道具、怪物掉落、NPC 商店等） |
| `src/main/resources/dbmigration/1.0__initial.sql` | EBean 自动生成的迁移脚本，含外键约束，为**规范化**版本 |

### 3.4 DCharacterSlot — `character_slots`（角色槽位）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Integer (PK) | 主键 |
| account | @ManyToOne → DAccount | 账号 |
| worldId | Integer | 世界 ID |
| charSlots | Integer | 角色槽位数 |

- **唯一约束**：`UNIQUE(acc_id, world_id)` — 每个账号在每个世界仅有一条记录
- **新建账号**：首次登录时 `getCharacterSlots()` 自动创建行，默认值为 `server.limit.characters`（默认 3）
- **扩容**：通过 `gainCharacterSlot()` 购买角色槽（上限 15），如行不存在则自动创建
- **GM**：GM 账号固定返回 15 个槽位，不查表

与 `DInventoryEquipment` 字段完全相同，关联 `csitems` 表。

| 唯一约束 | 说明 |
|---|---|
| `UNIQUE(inventory_item_id)` | 每个商城道具（csitems.id）最多一条装备属性记录 |

- **外键**：`inventory_item_id → csitems.id`，级联删除（`ON DELETE CASCADE`）

## 18. 设计要点总结

1. **EBean ORM 体系**: 所有实体继承 `io.ebean.Model`，使用 `@Entity`、`@OneToMany`、`@ManyToOne` 等标准 JPA 注解。查询 Bean（如 `QDAccount`）在编译期通过注解处理器自动生成。

2. **账号-角色两级结构**: `DAccount` → `DCharacter` 是核心关联链，大部分游戏数据挂在角色下。

3. **道具多态设计**: Item + Equipment 成对模式在背包、商城、快递、拍卖行、雇佣商人中复用，每个上下文有独立的一对表，而非共用一套。

4. **配置外置**: 数据库连接通过 `服务端配置.ini` 外部文件配置，不在源码中硬编码。EBean 的 `DataSourceConfig.loadSettings()` 负责解析。

5. **无级联删除**: 迁移脚本中外键约束使用 `on delete restrict`，应用层负责正确的删除顺序。原始 SQL dump 中仅 buddies 表有 `ON DELETE CASCADE`。

6. **静态数据**: WZ 系列表存储从游戏客户端导出的静态数据（道具属性、怪物技能、任务定义等），服务启动后加载到内存中供游戏逻辑使用。
