# 商城闪退 Bug 排查记录

## 问题概述

- **症状：** 角色 `absurdz` 进入商城（Cash Shop）时客户端 ACCESS_VIOLATION 闪退
- **客户端版本：** MapleStory v079
- **崩溃类型：** ACCESS_VIOLATION（客户端内存访问违规），概率性但高概率触发
- **首次记录：** 2026-05-02
- **状态：** 未解决

## CS_OPEN 封包结构（服务端→客户端，opcode=0x83）

```
 0: opcode (short, 2 bytes)
 2: -1L (long, 8 bytes)
10: 0 (byte, 1 byte)
─── addCharStats ───
11: charId (int, 4)
15: name (ASCII, 13 bytes fixed, null-padded)
28: gender (byte, 1)
29: skinColor (byte, 1)
30: face (int, 4)
34: hair (int, 4)
38: zeroBytes(24)
62: level (byte, 1)
63: job (short, 2)
65: connectData: str,dex,int,luk,hp,maxhp,mp,maxmp (8 shorts = 16 bytes)
81: remainingAp (short, 2)
83: remainingSp (short, 2)
85: exp (int, 4)
89: fame (short, 2)
91: gachaponExp (int=0, 4)
95: currentTime (long, 8)
103: mapId (int, 4)
107: spawnpoint (byte, 1)
─── 其他头部字段 ───
108: buddyCapacity (byte, 1)
109: bless (byte, 1)
110: mapleName (MapleAsciiString, length-prefixed)
...: meso (int, 4)
...: charId again (int, 4)
...: beans (int, 4)
...: 0 (int, 4)
...: 5 slot limits (5 bytes)
...: currentTime (long, 8)
─── 道具数据 ───
...: equipped items → write(0) → equipped nx → write(0)
...: equip inv → write(0) → use inv → write(0) → setup inv → write(0) → etc inv → write(0) → cash inv
─── 技能数据 ───
...: skillCount (short, 2)
...: for each skill: id(int), level(int), [masterLevel(int) if 4th job]
─── 后续 (硬编码商城目录等) ───
...: 大量硬编码的道具分类/推荐/新品数据
```

## 已排查：逐一排除的字段

所有测试均通过 JVM 系统属性（`-D` 参数）覆盖对应字段，将 absurdz 的数据改为与 absurdx 尽可能相同。

### 第一轮：道具数量怀疑（封包过大导致缓冲区溢出）

| 系统属性 | 作用 | 结果 |
|----------|------|------|
| `csopen.maxitems=3` | 每种背包最多写3个道具 | 偶尔1次成功，第二次闪退 |
| `csopen.maxitems=0` | 不写任何道具 | **仍然闪退** |

**结论：不是道具数量问题。**

### 第二轮：技能数量怀疑

| 系统属性 | 作用 | 结果 |
|----------|------|------|
| `csopen.maxskills=0` | 技能数写0 | 首次进入不崩，**第二次进入卡死**（症状不同：卡死而非闪退） |
| `csopen.maxskills=1` | 只写1个技能 | **稳定闪退** |

**结论：不是技能数量问题。** maxskills=0 时症状变化（卡死 vs 闪退）值得注意，可能是不同底层问题。

### 第三轮：角色等级

| 系统属性 | 作用 | 结果 |
|----------|------|------|
| `csopen.level=1` | 将等级覆写为1（与absurdx相同） | **仍然闪退**（同时设置了maxitems=0, maxskills=0） |

**结论：不是等级值问题。**

### 第四轮：职业

| 系统属性 | 作用 | 结果 |
|----------|------|------|
| `csopen.job=0` | 将职业覆写为0=Beginner（与absurdx相同） | **仍然闪退**（同时设置了level=1, maxitems=0, maxskills=0） |

**结论：不是职业值问题。**

### 四项全开测试

`-Dcsopen.level=1 -Dcsopen.job=0 -Dcsopen.maxitems=0 -Dcsopen.maxskills=0`

此时 absurdz 的 CS_OPEN 封包在 level/job/items/skills 方面与 absurdx 几乎一致，**但仍然闪退。**

## 未排查：仍可能触发崩溃的字段

这些字段在 absurdz 和 absurdx 之间仍然不同，且未被覆盖：

| 字段 | absurdz | absurdx | 风险评级 | 说明 |

| stats (INT) | 61 | 4 | **中** | 法师智力远高于新手，但short范围(0-32767)合法 |

| mapId | 101000001 | 20000 | **高** | 不同地图！101000001=魔法密林, 20000=新手村 |
| spawnpoint | ? | ? | 低 | 出生点 |
| buddyCapacity | ? | ? | 低 | 好友容量 |
| meso | ? | ? | 低 | 金币 |

### 重点怀疑：mapId

absurdz 在 `101000001`（魔法密林），absurdx 在 `20000`（新手教程地图）。商城封包中的 mapId 是否会影响客户端行为？例如客户端可能根据 mapId 预加载某些资源。

## 后续排查方向

### 方向A：CS_OPEN 后续封包

`CashShopOperation.java` 中，`warpCS()` 发送后立即调用 `CSUpdate()`，后者发送 4 个追加封包：
1. `showCashInventory(c)` — 商城库存
2. `sendWishList(chr, false)` — 愿望清单
3. `showNXMapleTokens(chr)` — NX/抵用券/枫叶点数
4. `getCSGifts(c)` — 礼物

**崩溃可能不是 CS_OPEN 本身，而是后续 4 个封包之一。** 排查方法：在 CSUpdate 之前加延迟或逐个屏蔽来定位。

### 方向B：字段级对比

将 absurdz 的数据库记录逐一修改为与 absurdx 相同（mapId, stats 等），测试哪一个改变后不再崩溃。这会比 JVM 属性覆盖更彻底，因为能覆盖所有字段。

### 方向C：字节级封包对比

清除旧的 hex dump，用完全相同的配置（重启服务器，统一JVM参数）分别获取 absurdz 和 absurdx 的 CS_OPEN + CSUpdate 全套封包，逐字节对比找到确切差异。

### 方向D：客户端反编译分析

使用 IDA 或 Ghidra 反编译 v079 客户端中处理 CS_OPEN 封包的函数，定位 ACCESS_VIOLATION 的具体触发指令和内存地址。

## 已发现的连带 Bug（已修复）

排查过程中发现并修复了以下 CS_OPEN 封包的独立问题：

1. **buddyCapacity 硬编码 20** → 应写 `chr.getBuddylist().getCapacity()`
2. **bless 字段硬编码 0** → 应写 `1`
3. **缺失 mapleName（账户名）字段** → 应写 `mplew.writeMapleAsciiString(chr.getName())`
4. **beans 硬编码 0** → 应写 `chr.getBeans()`

这些修复不影响 absurdz 的闪退问题（absurdx 即使在修复前也能正常进入商城），但它们是封包格式的正确修正。

### 封包调试方法

在发送封包之前，用临时代码将封包 hex dump 到文件：
```java
FileOutputStream fos = new FileOutputStream("/tmp/cs_open_hex.txt", true);
fos.write(("=== CS_OPEN for " + chr.getName() + " (" + csOpen.getBytes().length + " bytes) ===\n").getBytes());
fos.write(HexTool.toString(csOpen.getBytes()).getBytes());
fos.write("\n\n".getBytes());
fos.close();
```

**注意：** 重启服务器后 JVM 属性才会生效。

### 数据库查询

```sql
-- 角色基础属性
SELECT id, name, level, job, str, dex, int_, luk, hp, max_hp, mp, max_mp, exp, map, fame, meso
FROM characters WHERE name IN ('absurdz', 'absurdx', 'absurd');

-- 技能列表
SELECT c.name, s.* FROM skills s JOIN characters c ON s.character_id = c.id
WHERE c.name IN ('absurdz', 'absurdx') ORDER BY c.name, s.skill_id;
```
