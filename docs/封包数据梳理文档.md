# MapleStory v079 封包数据梳理文档

## 1. 概述

本项目（ms079）是一个 MapleStory v079 版本（Big Bang 前夕）的私服模拟器，客户端与服务端之间通过 **TCP 长连接** + **自定义二进制协议** 进行通信。

### 1.1 三层网络架构

| 服务器 | 端口 | 职责 |
|---|---|---|
| LoginServer | 9595（可配置） | 账号认证、世界列表、角色管理 |
| ChannelServer | 7575+（每频道递增） | 游戏核心逻辑、地图、战斗、社交 |
| CashShopServer | 8600 | 商城（Cash Shop）、拍卖行（MTS） |

### 1.2 协议栈

```
TCP
 └─ MINA (Apache MINA 2 NIO)
     ├─ MapleCodecFactory
     │   ├─ MaplePacketEncoder (编码：出站)
     │   └─ MaplePacketDecoder (解码：入站)
     └─ MapleServerHandler (路由：opcode -> handler)
```

## 2. 通信流程

### 2.1 连接建立

```
Client                              Server
  |                                    |
  |-------- TCP 连接 ----------------->|
  |                                    | 生成 AES OFB IV（收发各一对）
  |<------- Hello 包 (16 bytes) -------| 版本号 + IV + 地区码
  |                                    |
  | 后续所有包均使用 AES-OFB 加密       |
```

### 2.2 包格式

#### 密文层（网络传输）

```
| Header (4 bytes) | Encrypted Payload (N bytes) |
```

- **Header**: 由 `MapleAESOFB.getPacketHeader(length)` 生成，将明文长度编码为 4 字节加密头部
- **Payload**: 经两层加密的明文数据

#### 加密链

```
明文 → MapleCustomEncryption.encryptData() → MapleAESOFB.crypt() → 密文
密文 → MapleAESOFB.crypt() → MapleCustomEncryption.decryptData() → 明文
```

#### 明文层（解密后）

```
| Opcode (2 bytes, little-endian short) | Data (N bytes) |
```

数据写入使用 `MaplePacketLittleEndianWriter`（小端序），支持类型：
- `byte`, `short`, `int`, `long` — 整数类型
- ASCII 字符串（定长填充）
- Maple ASCII 字符串（长度前缀 + UTF-16LE 编码）
- 坐标 (2 shorts: x, y)
- 位移数据（Movement 片段列表）

## 3. Opcode 体系

### 3.1 目录

| 文件 | 行数 | 说明 |
|---|---|---|
| `src/main/java/handling/RecvPacketOpcode.java` | 734 | 客户端→服务端 opcode 枚举（~110个） |
| `src/main/java/handling/SendPacketOpcode.java` | 1029 | 服务端→客户端 opcode 枚举（~200个） |
| `src/main/resources/recvops.properties` | 351 | 接收 opcode 映射表 |
| `src/main/resources/sendops.properties` | 423 | 发送 opcode 映射表 |

### 3.2 Opcode 加载机制

`ExternalCodeTableGetter` 在运行时从 `.properties` 文件读取十六进制 opcode 值，通过反射注入到对应枚举常量中。这意味着修改 opcode 无需重新编译，只需编辑配置文件。

**recvops.properties 示例：**
```properties
PONG = 0x13
LOGIN_PASSWORD = 0x01
CHARLIST_REQUEST = 0x09
```

**sendops.properties 示例：**
```properties
LOGIN_STATUS = 0x00
SERVERLIST = 0x09
CHARLIST = 0x0A
```

## 7. 包处理层（Packet Handlers）

### 7.1 路由中心：`MapleServerHandler`

**文件**: `src/main/java/handling/MapleServerHandler.java`（1057 行）

通过 `messageReceived` 收到数据包后：
1. 读取 2 字节 opcode
2. 匹配 `RecvPacketOpcode` 枚举
3. 根据当前状态（登录服 / 频道服 / 商城服）分发给对应的 Handler

**核心路由表**:

| Opcode | Handler 方法 |
|---|---|
| PONG | `client.pongReceived()` |
| LOGIN_PASSWORD | `CharLoginHandler.login()` |

## 8. MINA 编解码层

### 8.1 类清单

| 文件 | 行数 | 说明 |
|---|---|---|
| `handling/mina/MapleCodecFactory.java` | 38 | 编解码工厂，组装 Encoder + Decoder |
| `handling/mina/MaplePacketDecoder.java` | 138 | 入站解码器（客户端→服务端） |
| `handling/mina/MaplePacketEncoder.java` | 119 | 出站编码器（服务端→客户端） |

### 8.2 解码流程（MaplePacketDecoder）

```
IoBuffer (原始字节流)
    │
    ├─ 1. 读取 4 字节 Header
    ├─ 2. client.getReceiveCrypto().checkPacket(header) 校验
    ├─ 3. MapleAESOFB.getPacketLength(header) 获取有效载荷长度
    ├─ 4. 等待凑齐 packetlength 字节
    ├─ 5. receiveCrypto.crypt(data) — AES-OFB 解密
    ├─ 6. MapleCustomEncryption.decryptData(data) — 自定义解密
    └─ 7. 输出 byte[] → IoHandler.messageReceived()
```

### 8.3 编码流程（MaplePacketEncoder）

```
MaplePacket
    │
    ├─ 1. 获取 payload = packet.getBytes()
    ├─ 2. MapleCustomEncryption.encryptData(payload) — 自定义加密
    ├─ 3. sendCrypto.crypt(payload) — AES-OFB 加密
    ├─ 4. sendCrypto.getPacketHeader(length) — 生成 4 字节头部
    ├─ 5. 拼装 header + encrypted payload → IoBuffer
    └─ 6. 发送到网络
```

特殊处理：未认证的新连接（无 `MapleClient` 属性）发送不加密的 Hello 包。

在 `MaplePacketEncoder` 和 `MaplePacketDecoder` 中，可通过 `MapleServerHandler.packetLogger` 开关启用封包日志，会打印：

## 12. 关键设计要点

1. **Opcode 外部化**: opcode 值存储在 `.properties` 文件中，运行时加载，修改无需重新编译
2. **两层加密**: AES-OFB（会话密钥） + 自定义加密（`MapleCustomEncryption`），双重保护
3. **OOP 工厂模式**: `MaplePacketCreator` 和专用 Packet 类使用静态工厂方法封装封包构建
4. **共享序列化工具**: `PacketHelper` 提供跨包复用的数据序列化方法，避免重复代码
5. **中央路由**: `MapleServerHandler` 通过一个巨大的 switch 语句集中管理所有入站包的路由
6. **Handler 分离**: 登录/频道/商城三种服务器模式共享同一套 MINA 编解码，但 Handler 各自独立
7. **异步回调**: `MaplePacket.onSend` 回调机制允许在包发送后执行自定义逻辑（如状态更新）
